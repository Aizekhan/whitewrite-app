# Маркет у Спільноті — специфікація (чернетка, не збудовано)

**Статус:** погоджено з власником 2026-11-02. Будуємо лише після остаточних цифр токеноміки й перевірки юристом базових шаблонів.
**Перший етап:** продаж **текстового ГДД** і **світу** (канон + історії). Файли (картинки, префаби, моделі) у пакет продажу не входять.

## 1. Рішення власника
| Питання | Рішення |
|---|---|
| Що продається | ГДД гри, світ або пакет «світ + гра» |
| Тип угоди | лише **викуп**: усі права переходять покупцю, продавець **втрачає проєкт повністю**; неексклюзивних ліцензій немає |
| Ліцензія перед продажем | обовʼязкова; заявку подає лише **Worldbuilder**; ліцензований проєкт можна продавати навіть на Free |
| Перевірка | 1–2 тижні; проєкт **заморожено** (лише читання); оплата перевірки — токенами сервісу |
| Ціна перевірки | за формулою: база (робота модератора) + ШІ-рецензія за обсягом тексту; цифри — після токеноміки |
| Оплата угоди | **Stripe Connect, варіант Б**: покупець платить грошима напряму продавцю, Stripe утримує **12%** на користь WhiteWrite. Продавець — продавець у чеку: повернення, суперечки з банком, податки — на ньому. WhiteWrite — майданчик з мінімальною відповідальністю |
| Юрист | **ШІ-агент** застосовує шаблони до кожної угоди; базові шаблони один раз перевіряє живий юрист |

## 2. Потік
1. **Заявка** (Біблія → ⚙ Налаштування → «Маркет»): що продається, ціна викупу, опис для покупця. Сервер перевіряє тариф (Worldbuilder) і резервує токени за перевірку (`paid-features.js` → `licenceReview`).
2. **Заморожування**: `worlds/{w}.freeze = { reason: 'licence', since, applicationId }` (і гра, якщо в пакеті). Правила Firestore забороняють клієнту писати в заморожений світ / гру; сервер — так само. Розморожування автором = відкликання заявки (токени не повертаються за вже виконані кроки).
3. **Знімок**: сервер робить замороженний знімок тексту (канон, історії, картки, квести, діалоги, план) у Storage `licences/{id}/snapshot.json` + хеш. Саме його перевіряють, показують покупцю й передають.
4. **Перевірка** (до 1–2 тижнів):
   - **автоматичні метрики**: «Готовність Біблії», пройдені ворота G0–G4, наповненість карток і розділів, граф квестів/діалогів, кількість «Неузгодженого», наповненість досьє, законів, хроніки, культури, історії; ♥, телеметрія, плейтести (для гри);
   - **ШІ-рецензія**: сильні / слабкі місця, що саме отримає покупець, узгодженість, схожість на відомі ігри чи бренди;
   - **ШІ-юрист**: ризики прав (чужі назви, торгові марки, реальні люди, згадки чужих ассетів), чернетка договору викупу;
   - **модератор**: остаточне рішення.
5. **Ліцензія**: рівень (Концепт → Готовий ГДД → Прототип → Vertical slice → Гра з гравцями), звіт перевірки, дата, хеш знімка. Лот зʼявляється в «Маркеті». Будь-яка зміна проєкту після ліцензії = ліцензія недійсна, лот знято (повторна перевірка дешевша).
6. **Покупка**: Stripe Checkout на акаунті продавця (direct charge) з `application_fee` 12%. Після `checkout.session.completed` (вебхук Connect) — угода.
7. **Передача**: власником світу / гри стає покупець (`owner` у `worlds/{w}` і `games/{g}`), історії світу — теж; доступ продавця зникає повністю; знімок і договір лишаються в архіві угоди.
8. **Суперечка**: «не відповідає опису» — модератор порівнює з знімком; гроші й повернення — за правилами Stripe на акаунті продавця.

## 3. Що бачить покупець до оплати
Вітрина лоту: огляд, рівень і звіт перевірки, зміст розділів і кількість карток, кілька повних карток на вибір автора, текст договору викупу. Повний знімок — лише після оплати.

## 4. Дані (Firestore, усе — лише сервер)
- `licenceApplications/{id}` — `{ uid, worldId, gameId?, kind: gdd|world|bundle, price, currency, status: review|approved|rejected|withdrawn, metrics, aiReview, legal, moderator, snapshotPath, snapshotHash, tokens, createdAt }`
- `marketLots/{id}` — публічна частина ліцензованого лоту (читають усі).
- `marketDeals/{id}` — `{ lotId, seller, buyer, amount, fee, stripe: { account, session, charge }, contractPath, status, at }`
- `sellers/{uid}` — `{ stripeAccountId, chargesEnabled, payoutsEnabled }` (Stripe Connect onboarding).
- `token_ledger/{id}` — незмінна книга руху токенів (поповнення, місячний бюджет, списання, оплата перевірки, повернення) з балансом після запису; **чеки** — `receipts/{id}` (PDF у Storage) для перевірок ліцензії й поповнень. Корисне й без маркету: користувач бачить історію токенів.

## 5. Cloud Functions
- `licence` — apply / withdraw / status; резерв і списання токенів; заморожування; знімок.
- `licenceReview` — метрики + ШІ-рецензія + ШІ-юрист → черга модератора.
- `market` — список лотів, сторінка лоту, `checkout` (Stripe Connect), адмін: approve / reject / takedown.
- `stripeConnectWebhook` — `account.updated`, `checkout.session.completed`, `charge.dispute.*`.
- `transferOwnership` — у транзакції після оплати.

## 6. Пізніші етапи
- **Картинки**: пошук копій в інтернеті (Google Vision web detection), метадані EXIF / C2PA, ШІ шукає водяні знаки й логотипи, декларація джерела; знайдено деінде без доказу прав — не допускається.
- **Префаби й 3D**: ассети Unity Asset Store / Fab перепродавати не можна за їхніми EULA; власні — лише з вихідними файлами й декларацією. Можливо, ніколи.

## 7. Перед запуском
- Остаточні цифри токеноміки → ціна перевірки в `functions/paid-features.js`.
- Живий юрист: правила маркетплейсу, договір продавця, шаблон договору викупу, правила суперечок.
- Звірити з документацією Stripe: тип акаунтів Connect і direct charges + `application_fee_amount`.
- База знань: «Маркет: як ми перевіряємо проєкти для продажу» (критерії, рівні, заморожування, ціни, передача прав, суперечки) — відкрито для всіх.
