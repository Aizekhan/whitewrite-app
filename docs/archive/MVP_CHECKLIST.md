# MVP_CHECKLIST — покроковий шлях до робочого MVP на whitewrite.com

> Правила: одна задача за раз · доказ (скрін + чиста консоль) ПЕРЕД комітом ·
> працюємо з папкою `app/` (колишня `core/prototype-full/`) як джерелом сайту ·
> НЕ переписувати JSX, НЕ TypeScript, НЕ «покращувати», НЕ дублювати ·
> кожна задача має формат Мета / Файли / Не чіпай / Тест-ГОТОВО.
> Не переходити до наступної, поки попередня не «ГОТОВО».

---

## ФАЗА A — Сайт = прототип 1:1 на проді

### A1. Папка прототипу → джерело сайту
- Мета: whitewrite.com віддає `app/` (перейменована `core/prototype-full/`).
- Файли: `firebase.json` (`"public":"app"`, rewrite `/`→`White.html`).
- Не чіпай: src/, Vite, public/main-app (мертві).
- Тест: whitewrite.com відкривається з `app/White.html`. Скрін.

### A2. Маг + assets вантажаться
- Мета: на лендінгу видно МАГА, лого, кнопку.
- Файли: перевірити шляхи `assets/*` усередині `app/`.
- Тест: Network → `StartBack.jpg`, `DeskBg.jpg`, шрифти, `cat-*`, `ph-*` = 200 (не 404). Скрін Network.

### A3. Вкладка браузера
- Мета: title «WhiteWrite», favicon = логотип (не «Vite + React + TS»).
- Файли: `White.html` `<title>` + `<link rel=icon>`.
- Тест: вкладка показує WhiteWrite + іконку.

### A4. Навігація шела
- Мета: перемикання Книга/Всесвіт/Режисер + На головну + userdock працюють на проді.
- Тест: усі переходи без 404, консоль чиста. Скрін кожного екрана.

---

## ФАЗА B — Акаунти (Firebase Auth)

### B1. Вхід/реєстрація
- Мета: модалка входу реально логінить (email + Google).
- Файли: `firebase-auth.js` + модалка у `White.html`.
- Тест: зареєструвався → у Firebase Auth зʼявився юзер → аватар у userdock. Скрін.

### B2. Гейт
- Мета: без входу «Проекти»/«Створити» → модалка входу.
- Тест: інкогніто → клік «Створити» → просить увійти.

### B3. Вихід
- Мета: кнопка виходу в Акаунті працює.
- Тест: вийшов → стан скинувся.

---

## ФАЗА C — Проєкти (Firestore)

### C1. Створення проєкту
- Мета: форма створення історії пише `projects/{id}` (owner:uid) у Firestore.
- Файли: `flow.jsx` (StoryForm) + `firebase-projects.js`.
- Тест: заповнив форму → Submit → документ у Firestore з усіма полями. Скрін Firestore.

### C2. Список проєктів
- Мета: «Проекти» показує реальні проєкти юзера.
- Тест: створив 2 → бачу 2 картки. Перезайшов — лишились.

### C3. Редагувати / Видалити
- Мета: edit (назва/опис/обкладинка) і delete (з підтвердженням) пишуть у Firestore.
- Тест: змінив назву → збереглось; видалив → зник. Скрін.

### C4. Firestore Rules (БЕЗПЕКА — P0)
- Мета: `owner == request.auth.uid` (НЕ `if true`).
- Тест: чужий юзер не читає чужі проєкти. Деплой rules.

---

## ФАЗА D — Ядро MVP: генерація сцени (Gemini)

### D1. Форма → книга
- Мета: після створення проєкту відкривається книга (ритуал → розворот), без чорного екрана.
- Файли: `app.jsx` (стейдж-машина), `book.jsx` (окремий render ритуалу).
- Тест: створив → ритуал → книга. Консоль чиста. Скрін.

### D2. Scene Intent
- Мета: екран «Що далі?» (7 напрямів + свій) показується й передає вибір у генерацію.
- Файли: `pages.jsx` (SceneIntentPage).
- Тест: обрав напрям → пішов запит генерації.

### D3. Gemini генерує (canon-aware)
- Мета: реальний виклик Cloud Function, текст від Gemini, читає `project.canon`.
- Файли: `firebase-ai.js` + Cloud Function.
- Тест: натиснув → отримав реальний текст сцени (не мок). Лог Function = success.

### D4. Збереження сцени
- Мета: згенерована сцена пишеться в `projects/{id}/scenes/{sceneId}`.
- Файли: `firebase-scenes.js`.
- Тест: сцена в Firestore. Скрін.

### D5. Книга показує РЕАЛЬНУ сцену
- Мета: книга рендерить збережену сцену, не мок «Червоний сигнал».
- Файли: `book.jsx` (читання з Firestore).
- Тест: відкрив книгу → бачу саме згенеровану сцену. Пагінація працює.

### D6. 🎯 НАСКРІЗНИЙ ТЕСТ MVP
- Реєстрація → створив історію → Scene Intent → Gemini згенерував → книга показує цю сцену.
- Консоль чиста, rules закриті, усе на whitewrite.com.
- **Це і є живий MVP.** Скрін усього циклу.
