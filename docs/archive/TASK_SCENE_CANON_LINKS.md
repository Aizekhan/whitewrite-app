# TASK — Scene ↔ Canon relational links (`scene.canonRefs`)

> Мета: звʼязати сцени з каноном через ID-посилання, щоб фільтри, Хроніка й
> Reconstruction працювали на реальних звʼязках. БЕЗ копіювання сутностей.
> UI не чіпати — це робота під капотом (дані + extraction).

## СИТУАЦІЯ (поясни Claude Code)
Зараз canon (`project.canon`) і сцени (`projects/{id}/scenes`) живуть окремо й
НЕ повʼязані. Тому SceneMenu-фільтр по сцені нічого не фільтрує, і Reconstruction
не знає, які сцени зачепить зміна сутності. Треба, щоб кожна сцена знала, які
сутності їй належать — через їхні стабільні ID, не копії.

## ІНВАРІАНТ (не порушувати)
- Canon = джерело правди; сутність існує ОДИН раз у `project.canon`.
- Сцена зберігає лише **ID** (opaque). Rename сутності не ламає звʼязок.
- Зворотний звʼязок («у яких сценах сутність») — ДЕРИВУЄТЬСЯ скануванням сцен,
  НЕ зберігається окремо. Одне джерело, нуль розсинхрону.

## ЩО САМЕ ЗБЕРІГАЄ СЦЕНА
Кожна сцена отримує поле `canonRefs` з ID усіх 5 типів канону + наратив-метадані:
```
scenes/{sceneId}
  n, act, title, text, intent, recon
  canonRefs: {
    characters: [CanonId, ...]   // персонажі, що зʼявляються/говорять у сцені
    locations:  [CanonId, ...]   // де відбувається сцена
    events:     [CanonId, ...]   // події, що стаються/згадуються
    factions:   [CanonId, ...]   // задіяні фракції
    artifacts:  [CanonId, ...]   // предмети, що фігурують
  }
  pov?: CanonId                  // (опц.) чий POV — id персонажа
  arc?: string                   // (опц.) сюжетна лінія/арка для нелінійності
```
> Усі 5 канон-сутностей: **characters, locations, events, factions, artifacts.**
> Хроніка = вид на events (порядок по act/часу) — окремо зберігати не треба.

## ЗВІДКИ беруться refs
1. **Auto (головне):** Canon Extraction після генерації сцени знаходить згадані
   сутності → пише їхні ID у `scene.canonRefs` (а нові, яких нема в canon, → у
   inferred-чергу; після підтвердження теж лінкуються).
2. **Бекфіл:** для вже згенерованих сцен — разовий прохід extraction, що проставляє refs.

## КРОКИ (по одному, з доказом перед комітом)
1. Додати тип/схему `scene.canonRefs` (5 масивів ID) — `firebase-scenes.js`, types.
2. Canon Extraction записує ID у `scene.canonRefs` (підтверджені сутності → лінк до сцени).
3. SceneMenu-фільтр читає `scene.canonRefs` (а не порожнечу) → фільтр реально працює.
4. Reconstruction `wAffected(type,id)` шукає сцени, де id ∈ `canonRefs[type]`.
5. Бекфіл наявних сцен (проставити refs).

## ГОТОВО КОЛИ
- Згенерував сцену → у Firestore `scene.canonRefs` заповнені ID (не порожні).
- SceneMenu: обрав «Сцена 2» → список сутностей відфільтрувався саме на її учасників.
- Rename персонажа в canon → усі сцени бачать нове імʼя (бо лінк по id).
- Жодних копій сутностей у сценах — лише ID.
