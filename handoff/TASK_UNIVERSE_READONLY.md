# ЗАВДАННЯ ДЛЯ CLAUDE CODE — Всесвіт (Canon) на реальних даних

> ОБСЯГ ЦІЄЇ ІТЕРАЦІЇ: підключити стовп **Всесвіт** до реальних даних Firestore
> і дати ПЕРЕГЛЯД канону по справжньому проєкту.
>
> ❌ НЕ робимо зараз: редагування канону (CRUD), inferred-чергу, реальну
>    Reconstruction-регенерацію, hidden canon. Це наступні ітерації.
> ❌ НЕ робимо: жодних змін UI/дизайну, нових екранів, нових кнопок.

## ГОЛОВНИЙ ПРИНЦИП
**UI вже готовий і правильний — НЕ чіпай вигляд.** Дерево, воркспейси, картки,
профіль, граф, Хроніка, dropdown категорій і сцен — усе намальовано в
`wt-*.jsx`. Твоя задача — **замінити мок-дані на реальні з Firestore**, нічого
не перемальовуючи. Якщо після твоєї роботи вигляд змінився — ти зробив зайве.

## ЩО САМЕ (по кроках, по одному, з доказом перед комітом)

### Крок 1 — читати canon з Firestore (не з моку)
- Зараз дерево живиться з `wt-world.jsx` (мок `WORLD`).
- Підключи його до `project.canon` поточного проєкту (Firestore), той самий
  формат, ті самі поля. Усі 5 категорій: **Персонажі, Локації, Події, Фракції,
  Артефакти** + **Хроніка** (вид на Події в порядку актів).
- Файли: `firebase-canon.js` (новий: getCanon(projectId)), `wt-world.jsx`/
  `wt-workspace.jsx` (джерело даних), `wt-app.jsx`.
- Готово коли: відкрив свій проєкт → Всесвіт показує канон САМЕ цього проєкту з
  Firestore; інший проєкт → інший канон; новий проєкт → порожні категорії
  (не «Червоний сигнал»-мок). Вигляд ідентичний прототипу.

### Крок 2 — canon-aware генерація читає той самий canon
- Переконайся, що генерація сцен бере контекст із того ж `project.canon`
  (а не з моку), і `deriveMemory(canon)` дає AI актуальні сутності.
- Готово коли: додав у canon персонажа (поки вручну в Firestore) → нова сцена
  його враховує.

### Крок 3 — Хроніка з реальних подій
- Хроніка-серце показує реальні Події проєкту, впорядковані по актах/часу.
- Готово коли: події з Firestore зʼявляються в Хроніці в правильному порядку.

## ПРАВИЛА (залізні)
1. Вигляд НЕ міняється. Копіюй поведінку з прототипу, підмінюй лише джерело даних.
2. Працюй ПО ОДНОМУ кроку. Після кожного — скрін + перевірка Firestore ПЕРЕД комітом.
3. Не додавай кнопок/форм/екранів — редагування буде наступною ітерацією.
4. Canon = джерело правди; Memory = derived View (не писати напряму).
5. Якщо «здається, що треба щось домалювати» — СТОП, спитай. UI вже повний.

## ЯК Я ПЕРЕВІРЮ
Відкрию свій проєкт → Всесвіт → бачу СВІЙ канон з Firestore (не демо), вигляд
1:1 як прототип, консоль чиста. Це і є «готово» для цієї ітерації.

> НАСТУПНІ ітерації (НЕ зараз, не починай): CRUD-редагування канону →
> inferred-черга → реальна Reconstruction. Повна карта — у WORLDTREE_DEV_PLAN.md.
