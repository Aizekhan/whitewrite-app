# UI PORT — план перенесення прототипу WhiteWrite у прод (для Claude Code)

> Прототип = **жива специфікація**. Кожен файл нижче — еталон вигляду й поведінки.
> Дані-шар (Canon міграція, фази 1-4) уже зроблено — тепер порт UI поверх нього.
> Принцип: **не вгадувати** — відкривати файл прототипу й переносити точні значення
> (токени, копірайт, стани кнопок, анімації) у реальні React-компоненти.

## Як підходити (золоте правило)
1. Порт **по екрану**, не по файлу скопом. Один екран → запрацював → наступний.
2. Для кожного екрана: спершу **верстка + токени** (піксельна відповідність), тоді **підключення до реальних даних** (Firestore/canon), тоді **кожна кнопка**.
3. Після кожного екрана — звірка з прототипом пліч-о-пліч. Не йти далі, поки не збігається.
4. Дизайн-токени винести в один `tokens.css`/theme один раз (значення — нижче), далі всі компоненти беруть звідти.

## Чек-лист функціоналу (кожна має працювати)
**Шел / навігація**
- [ ] Верхнє меню контекстне: головна (Проекти·База знань·Маркетплейс) / в історії (Книга·Всесвіт·Режисер)
- [ ] Лого-дерево → головна; кнопка «На головну» вгорі-справа на всіх екранах
- [ ] Стрілка-згортання меню в режимі читання
- [ ] Токени + аватар знизу-зліва наскрізно; вхід/реєстрація (модалка), вихід; гейт «Проекти» без входу

**Створення історії**
- [ ] Форма: назва, опис, режим (Guided/Auto), обсяг(+серії), фінал, жанри(до 4), довжина сцен, **діалоги (авто за жанром)**
- [ ] Анімація мага → плавний blur-перехід у книгу

**Книга**
- [ ] Перегортання (стрілки на кутках + кружечки з вікном), пагінація тексту по аркушах
- [ ] Перемикач сцени/акта; персистентність позиції
- [ ] Режим редагування (кнопка-олівець), Хранитель: нові сутності (тип) + конфлікти → canon
- [ ] Scene Intent «Що далі?» (напрями + свій опис) → наступна сцена
- [ ] Закладки канону; панель шрифту (Aa)

**Всесвіт**
- [ ] Дерево + Хроніка; воркспейс категорії: пошук/фільтр/сорт/групи; види Картки·Список·Граф
- [ ] Профіль сутності + клікабельні звʼязки; перемикач категорії + сцена-лінза
- [ ] Картки: редагування інфо (а не лише фото); обмеження (обсяг ≥ написаних сцен); видалення з підтвердженням
- [ ] Overlay реконструкції: тип зміни → стратегія → план → виконання

**Режисер**
- [ ] Розрахувати к-ть кадрів; додати/редагувати/видалити кадр; намалювати + варіанти(3-5)
- [ ] **Діалоги в кадрі** (кілька реплік: хто·емоція·текст, тривалість озвучки)
- [ ] Візуальний канон: набір референсів (генерувати+підтвердити / завантажити / видалити), LoRA-пороги (3/15/20)

**Інше**
- [ ] Маркетплейс (читати/оцінювати), Акаунт (профіль·аватар·плани·токени), Замовити книгу (скоро), База знань (пошук·категорії·читалка)

## Порядок портування (рекомендований)
1. **Токени + шел + навігація** (каркас, на ньому все тримається).
2. **Книга-читалка** (читання + пагінація + сцена/акт) — серце продукту.
3. **Створення історії** (форма → книга).
4. **Всесвіт** (дерево → воркспейс → профіль) — звʼязати з реальним canon.
5. **Режисер** (розкадровка + діалоги + візуальний канон).
6. **SceneEditor + Хранитель** — звʼязати з готовим EDIT→CANON бекендом.
7. **Reconstruction overlay** — звʼязати з рушієм.
8. Маркетплейс · Акаунт · База знань · Замовити книгу.

## Що НЕ переносити
- iframe-архітектуру шелу (`ww-embed.js`) — у проді це справжній роутер, стовпи = маршрути одного SPA.
- `ws-data.jsx` проєкцію — Режисер читає canon напряму.
- in-browser Babel — прекомпіляція як завжди.

> Передати разом із: `CANON_SCHEMA.md`, `EDIT_TO_CANON.md`, `CLAUDE.md`, `SESSION_DIGEST.md`.
> Робити по одному екрану, звіряючись із прототипом. Не йти далі, поки кнопки екрана не працюють.
